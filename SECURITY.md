# Security policy

Security issues must be reported privately so maintainers can investigate and
coordinate a fix before details enable exploitation.

## Supported versions

Until versioned releases exist, security fixes apply to the current default
branch. Historical snapshots and third-party forks are not maintained by this
project.

## Report a vulnerability

Email `marco@torphi.com.br` with the subject `Security - Bullgate Access`.

Include only the information needed to investigate:

1. affected component, route, type, or revision;
2. observed or potential impact;
3. minimal reproduction steps;
4. environment and relevant version information;
5. redacted evidence;
6. a safe contact method for follow-up.

Do not send valid credentials, passwords, OTPs, reset tokens, session tokens,
provider secrets, or another person's data. If sensitive evidence is essential,
first describe what exists and arrange a safer transfer method.

## Expected response

The project aims to acknowledge a report within five business days and provide
an initial assessment within ten business days. These are communication goals,
not resolution guarantees.

## Responsible research

Use only systems, accounts, and data you own or are explicitly authorized to
test. Avoid denial of service, spam, social engineering, persistence, and access
to third-party data. Stop immediately if you encounter data you were not
authorized to access, and retain only the minimum evidence required.

This policy does not authorize testing third-party providers or infrastructure.
The project currently offers no bug bounty or guaranteed payment.

## Disclosure

Please do not publish exploitable details before a fix, mitigation, or agreed
disclosure date exists. Credit is offered when desired and safe.

Documentation errors, broken links, and non-security proposals may use public
issues after the repository is opened.
